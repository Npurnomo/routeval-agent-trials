# Package-value pilot: frozen protocol

October 20, 2026. This is the four-session pilot accepted in the latest chat,
before the larger documentation/skill qualification experiment. It tests package
availability against ordinary Python, not skill instructions. Both tasks receive
equal priority.

## Design

| Session | Track | Condition |
|---|---|---|
| A | Integration | Python standard library only |
| B | Integration | Python plus published Routeval 0.1.1 |
| C | Evaluation | Python standard library only |
| D | Evaluation | Python plus published Routeval 0.1.1 |

Use fresh contexts with the same inherited model/settings; do not claim
different-model or external-user independence. Each session owns a separate work
area. Ten-minute budget from the first tool action; blocked/late sessions remain
in the record. Initial environment installation is prepared by the chair and
excluded from agent timing. No provider calls, paid services, package/site code
changes, public publication or deployment are part of participant work.

Each pair receives byte-identical task inputs, the same full record-format guide,
owner requirements and neutral submission format. Only installed package
availability and its normal discovery surface differ. No solution or expected
candidate judgments are given. With-package scripts use public exports, documented
CLI and full artifacts, not internal helper imports or terminal-table scraping.

Inputs are frozen in `frozen-inputs.json`; expected results were saved before
dispatch in `expected.json`. The preparation record pins their digest. Participants
must not read chair records, earlier reviews, public study answers or each
other's files. These are instruction and hash controls in a shared workspace,
not an OS isolation or authenticity guarantee.

Three child slots are available. Launch C, B and A first; launch D when a slot
opens. Record actual dispatch/completion times and treat latency as descriptive:
overlap, scheduling, inference and tool delays make it unsuitable for a causal
productivity claim. No author coaching during the initial task. Record any
necessary assistance and retain the initial submission before corrections.

## Prespecified checks

- All candidate recommendations against the hidden expected result register:
  four per integration session, seven per evaluation session (22 judgments).
- Protected input/target integrity and complete attempted population.
- Required checks and evidence coverage; unknown bills must remain unknown.
- Integration row mapping, charges and retained billed failures.
- Critical-cohort, latency, incompatible scorer and protected-target failures.
- Actual commands and process results, runnable artifacts and stated limitations.
- Authored runtime lines with a clear counting method and responsibility split.
- Reported difficulties, assumptions, interventions and requested improvement.

Known input failure types are part of each owner's stated requirements. Expected
verdicts remain hidden. A copied artifact with unchanged declared hashes but
changed protected targets demonstrates the need for owner-controlled target
identity; it is not automatically a package defect.

## Analysis and stopping

Score original outputs before reading preference feedback. Report each track and
condition separately. An incorrect approval, dropped failure or fabricated cost
is a substantive failure; a malformed feedback record is a separate reporting
failure. Do not substitute a successful rerun for a failed original.

Compare correctness, evidence omissions, custom logic and interventions before
descriptive timing or line counts. One trial per condition cannot establish a
general advantage or reliability. Record package limitations and caller work
even if both approaches succeed.

After the four original submissions are frozen, give each participant one bounded
optional follow-up on new saved records. Make Routeval available to both original
conditions without requiring it. Observe actual tool/code use and the result;
record opinions separately. This is observed choice in a controlled task, not
outside adoption or market preference. Cap the follow-up at five minutes.

The chair may repair a participant prototype for a later public reference
implementation, preserving the original version, the difference and its reason.
Publication should label this as a small synthetic controlled pilot. A reusable
skill and the larger 12-session experiment remain later work.
